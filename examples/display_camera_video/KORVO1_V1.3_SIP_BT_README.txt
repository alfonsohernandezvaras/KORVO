KORVO1 V1.3.0 - SIP + BLUETOOTH HFP AG LAB
============================================
Base: KORVO1 V1.2.0 reciprocal-IP Gateway pairing (working base preserved)
Target: ESP32-S31-Korvo-1 / ESP-IDF 6.1

ARCHITECTURE
------------
Gateway remains field I/O only:
  GPIO39 CALL -> event call.short_press / call.long_press -> WebSocket -> KORVO

KORVO owns the intercom stack:
  SIP REGISTER / INVITE / ACK / CANCEL / BYE
  incoming + outgoing calls
  RTP G.711 PCMA (PT8) / PCMU (PT0), 8 kHz
  Bluetooth Classic HFP Audio Gateway (AG)
  Bluetooth HF scan / pair-connect / disconnect / forget from KORVO webserver
  HFP audio path via HCI
  RTP <-> HFP PCM bridge

WEB
---
New menu: INTERCOM

SIP configuration:
  enable
  Asterisk/PBX server
  server/local SIP ports
  RTP port
  KORVO extension
  SIP username/password
  display name
  operator/central extension
  REGISTER expiry
  REGISTER / CALL OPERATOR / ANSWER / REJECT / HANGUP

Bluetooth configuration:
  enable HFP AG
  local Bluetooth name
  legacy PIN
  auto-connect
  SCAN
  PAIR / CONNECT
  DISCONNECT
  FORGET
  HFP SLC / SCO audio / codec status

APIs:
  GET /api/korvo/sip/status
  GET /api/korvo/bluetooth/status

HMI
---
The permanent bottom status strip now shows KORVO local SIP state.
Examples: REG/IDLE, LLAMANDO, TIMBRANDO, ENTRANTE, EN LLAMADA.
No new overlay is added over the camera/detection ROI.

CALL BUTTON
-----------
Gateway event call.short_press:
  SIP idle/terminal -> call configured operator extension
  SIP incoming      -> answer

Gateway event call.long_press:
  calling/ringing/incoming/connected -> hang up

Bluetooth HF buttons:
  answer -> SIP answer
  hangup -> SIP hangup
  dial   -> SIP call

LAB AUDIO V1.3
--------------
Initial audio path deliberately uses narrow-band HFP CVSD / 8 kHz PCM and
G.711 PCMA/PCMU / 8 kHz. This avoids resampling while proving the complete
real call path.

AEC / noise reduction / AGC are NOT enabled in this first integration.
They are a later step after real bidirectional audio is proven.
Simulation is NOT part of V1.3; it remains for the end of integration.

ESP-IDF CONFIG ADDED
--------------------
Bluetooth Classic + Bluedroid + HFP AG + one SCO/eSCO connection + HCI audio.
WBS/mSBC is disabled in this first lab build so HFP stays CVSD 8 kHz.

BUILD
-----
Use the same ESP-IDF 6.1 environment that built KORVO1 V1.2.0.
Do not erase NVS unless an intentional factory reset is wanted.

  idf.py build

Then flash using the normal project procedure.

FIRST TEST ORDER
----------------
1. Boot V1.3 and verify existing KORVO/Gateway pairing still shows PAIRED.
2. Open KORVO webserver -> INTERCOM.
3. Enable Bluetooth HFP, save, put the hands-free speaker/headset in pairing,
   SCAN and PAIR / CONNECT. Verify HFP SLC CONNECTED.
4. Enter Asterisk SIP settings, enable SIP and save. Verify REGISTERED / idle.
5. Use CALL OPERATOR from web first.
6. After signaling works, press physical GPIO39 CALL on Gateway.
7. During a connected call verify SCO audio + RTP bridge are RUNNING.

NOTE
----
This package was prepared as source integration. It was not compiled inside
ChatGPT's container because the ESP-IDF 6.1 ESP32-S31 toolchain is not present
there. The first user build is therefore the compile validation step, exactly
as with the previous project updates.

V1.3.1 BUILD FIX
----------------
For ESP-IDF 6.1-dirty with GCC 15.x, CONFIG_COMPILER_DISABLE_DEFAULT_ERRORS=y
is enabled because Bluedroid bta_dm_act.c can emit -Wstringop-truncation from
framework code and otherwise stops the build under global -Werror.
