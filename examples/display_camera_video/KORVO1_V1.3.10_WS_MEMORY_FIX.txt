KORVO1 V1.3.10 - GATEWAY WEBSOCKET MEMORY/RETRY FIX

Based on the V1.3.9 runtime log.

Root cause observed:
- Gateway manager retried esp_websocket_client_start() every 500 ms.
- esp_websocket_client task creation failed repeatedly.
- repeated client init/start/destroy pressure ended with event-loop queue allocation failures and abort().

Changes:
- WebSocket task stack: 8192 -> 4096 bytes (the Espressif component default is 4 KiB).
- Gateway manager task stack: 8192 -> 4096 bytes.
- WebSocket RX/client buffer: 8192 -> 4096 bytes; Gateway JSON protocol does not need 8 KiB frames.
- Failed WebSocket starts now back off 5 seconds instead of retrying every 500 ms.
- A manual/reconfiguration restart bypasses the backoff once.

No changes to Bluetooth pairing UI, SIP, alarms, camera ROI, or IP pairing semantics.
